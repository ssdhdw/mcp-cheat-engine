# Cheat Engine MCP GUI bridge — первый прототип

MCP STDIO → Python → локальный Windows named pipe → Lua внутри Cheat Engine →
`synchronize()` → реальные объекты GUI. Отдельная копия таблицы не создаётся:
агент и пользователь работают с одним `AddressList`. Добавленная запись выделяется,
изменение значения отображается в таблице, заморозка меняет обычный checkbox CE.
Отдельное окно **MCP agent activity** показывает время, операцию и результат,
хранит последние 200 действий. Значения в журнал не выводятся.

## Возможности первой версии

| MCP tool | Действие |
| --- | --- |
| `get_state` | PID выбранного процесса и число записей |
| `list_processes` | Процессы, доступные CE |
| `attach_process` | Выбор процесса в CE |
| `list_records` | Чтение живой таблицы, страницы до 200 записей |
| `add_record` | Создание видимой числовой записи по адресу/выражению CE |
| `set_record_value` | Запись через `MemoryRecord.Value` |
| `freeze_record` | Изменение `MemoryRecord.Active` |
| `stop_bridge` | Отключение моста до перезапуска CE |

Типы: `byte`, `word`, `dword`, `qword`, `float`, `double`. Запись/заморозка
существующих скриптов и групп отклоняется. Перед мутациями проверяется
`expected_pid`, чтобы ручное переключение процесса не перенаправило запись.
PID не защищает от повторного использования того же PID после перезапуска процесса.
Изменение значения возвращает фактически прочитанное CE значение; целевая программа
может немедленно изменить его снова. Не считайте ответ подтверждением долговременного сохранения.

Сканирование памяти, отладчик, указатели, дизассемблер, Mono/.NET и инъекции
в этой версии ещё не реализованы. Произвольного `execute_lua` нет.

## Запуск на Windows

Требуется установленный/собранный Cheat Engine с Lua API и Python 3.11+.
Пересборка CE для этого прототипа не нужна. Исходники CE собираются по инструкции
в корневом README. В fork включён готовый `Cheat Engine/bin/autorun/ce_mcp.lua`:
при запуске CE из этой папки мост стартует автоматически через штатный autorun.

1. В папке `mcp` создайте окружение и установите зависимости:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

2. Для установленного CE один раз установите автозапуск из PowerShell
   (для `Program Files` может потребоваться запуск PowerShell от администратора):

   ```powershell
   .\.venv\Scripts\python.exe install_autorun.py --ce-dir 'C:\Program Files\Cheat Engine'
   ```

   Перезапустите CE. Окно **MCP agent activity** появится автоматически;
   открывать Lua Engine и выполнять команды больше не нужно. Скрипт полностью
   автономный: после установки ему не требуется путь к клонированному репозиторию.
   Повторите установку после обновления моста. Отменить автозапуск:

   ```powershell
   .\.venv\Scripts\python.exe install_autorun.py --ce-dir 'C:\Program Files\Cheat Engine' --uninstall
   ```

   Удаление применяется после перезапуска CE. Уже запущенный мост можно отключить
   инструментом `stop_bridge`. Автозапуск активирует его снова при следующем запуске CE.

   Для ручного запуска без установки autorun остаётся вариант через Lua Engine:

   ```lua
   dofile([[C:\path\to\mcp-cheat-engine\mcp\ce_bridge.lua]])
   ce_mcp.start()
   ```

   Должно появиться окно журнала. Этот ручной вариант не нужен при установленном autorun.
   Для нескольких экземпляров CE используйте разные имена pipe: `ce_mcp.start('ce-mcp-2')`.

3. В конфигурации MCP-клиента укажите абсолютные пути к Python и `server.py`:

   ```json
   {
     "mcpServers": {
       "cheat-engine": {
         "command": "C:\\path\\to\\mcp\\.venv\\Scripts\\python.exe",
         "args": ["C:\\path\\to\\mcp\\server.py"],
         "env": {
           "CE_MCP_PIPE": "ce-mcp"
         }
       }
     }
   }
   ```

   Это общий пример JSON; расположение и формат настроек зависят от клиента.
   Сервер работает через STDIO и запускается самим MCP-клиентом.

## Проверка в живом GUI

На Cheat Engine Tutorial или своей тестовой программе:

1. `list_processes`, затем `attach_process(pid)` и `get_state`; проверить выбранный
   процесс в GUI.
2. Найти доступный числовой адрес средствами CE, вызвать
   `add_record(expected_pid, address, "MCP test", "dword")`.
   Проверить появление и выделение записи.
3. Передать возвращённый ID в `set_record_value`; сравнить возвращённое значение,
   колонку Value в GUI и значение в тестовой программе.
4. `freeze_record(..., true)`, затем `false`; проверить checkbox и поведение значения.
5. Вручную изменить описание/значение в CE и проверить `list_records`.
6. Вручную переключить процесс; запись со старым `expected_pid` должна завершиться ошибкой.
7. Вызвать `stop_bridge`; следующая команда должна получить ошибку соединения.

## Протокол и ограничения

Одна команда на соединение. Кадр: uint32 little-endian длина, затем payload,
максимум 1 MiB. Запрос — UTF-8 поля с percent encoding, разделённые TAB:
`operation, arguments...`. Ответ — UTF-8 JSON:
`{"ok":true,"result":...}` или `{"ok":false,"error":"..."}`.
Аутентификации нет: локальные процессы, имеющие доступ к pipe, могут вызывать
команды моста. Это локальный IPC, не удалённый сетевой сервис. Upstream
`createPipe` даёт широкий локальный ACL. Локальный процесс может занять единственное соединение
и заблокировать worker; GUI продолжит работать. Для промышленной версии нужен
собственный Pascal pipe server с ACL текущего пользователя и таймаутами чтения.

Python отменяет ожидание по дедлайну 10 секунд. Таймаут/обрыв после отправки
может означать, что команда уже выполнилась: сначала прочитайте состояние,
не повторяйте мутации автоматически. Автоматических повторов нет.
Работа синхронизирована с GUI, поэтому длительный обработчик может задержать интерфейс.
Мост не меняет прав CE: при необходимости доступа к повышенному процессу права
нужно обеспечить при запуске CE. Закрытие окна журнала скрывает его; отключайте
мост через `stop_bridge` или завершение CE. Повторный запуск требует перезапуска CE.

## Автоматические тесты

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s . -p 'test_*.py' -v
```

Тесты выполняют настоящий Lua-код с подменой CE API, проверяют обращение к GUI
только через `synchronize`, Unicode/экранирование, проверку PID,
валидацию, реальный Windows named pipe и MCP initialize/list_tools/error через STDIO.
Также проверяются автоматический запуск упакованного скрипта, повторная загрузка,
установка/обновление/удаление и сохранность чужих скриптов. После изменения
`ce_bridge.lua` обновляйте копию для сборки: `python install_autorun.py --package`.
Они не подтверждают совместимость с конкретной сборкой CE и визуальное поведение;
для этого необходим ручной сценарий выше.
